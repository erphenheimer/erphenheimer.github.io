24GB显存下的RNA-蛋白复合物结构预测——世界科学智能大赛初赛技术复盘

24GB显存下的RNA-蛋白复合物结构预测——世界科学智能大赛初赛技术复盘

初赛单人队伍，全国排名 199/3475（前 5.7%）。本文按时间顺序复盘全程：我们面对的赛题与资源约束、每个阶段遇到的具体技术问题、采取的方案、实测得分，以及被证伪的路线。所有数据来自本地迭代日志与提交记录。

0. 协作方式说明

本次参赛采用人机协作的工程方式：代码实现、参数调整与文档整理由 AI 辅助完成；赛题分析、方案取舍、方向决策与提交确认由人完成。本文整理的即后者——每一轮"下一步做什么"的判断依据。

1. 赛题与约束条件

1.1 赛题

第四届世界科学智能大赛（上海科学智能研究院、复旦大学主办）生物结构预测赛道：RNA-蛋白复合物三维结构预测。输入为蛋白氨基酸序列与 RNA 核苷酸序列，输出复合物三维结构（CIF 格式），以 RMSD / TM-score / lDDT 对照真实结构评分。

初赛共三道测试题，复杂度递进：

赛题 组成 总 token 数 特点
r001 蛋白二聚体 2×237aa + 34nt RNA 508 规模最小
r002 2×228aa + 2×215aa 蛋白 + 2×114nt RNA 1114 链数最多
r003 单链 1357aa 蛋白 + 58nt RNA 1415 单链最长

三题等权计入总分，每题提交一个 CIF 文件。

1.2 资源约束

  • 算力：魔搭（ModelScope）免费 A10，24GB 显存，单卡。无本地 GPU。
  • 时间：初赛窗口内可多次提交，但每次提交需等待线上评测反馈。
  • 关键矛盾：结构预测模型的注意力机制显存开销为 O(N²)，r003 的 1415 tokens 恰好处在 24GB 显存的临界区之外——这决定了整场比赛的技术主线。

2. 阶段一：流程打通与基线建立（v1）

技术选型为 Protenix（开源结构预测模型，base_default_v0.5.0），理由：原生支持 RNA-蛋白复合物输入、提供现成推理 CLI、模型规格有 base/mini/tiny 三档可降级。

基线跑通后得分约 0.32。此阶段踩掉的工程坑，后续全部固化进了脚本：

问题 原因 处理
CLI 启动 ImportError deepspeed 与推理路径冲突 pip uninstall deepspeed
protenix predict 不存在 2.x 旧版 CLI 为 protenix pred，新版为 predict 脚本内做双格式探测
-s 参数语义 -s 是 seed，采样数是 -e 查 -h 确认
镜像源包损坏 阿里云镜像 hash 校验失败 切换官方 PyPI

3. 阶段二：MSA 消融事故（v2 → v2.1）

为缩短单次推理时间，v2 尝试关闭 MSA（多序列比对）。

MSA 的作用：将同源蛋白的多物种序列对齐，统计共突变位点——协同突变的位置在三维结构中倾向于空间邻近，这是结构预测最强的先验信号之一。关闭后模型退化为近似"从单序列盲猜折叠"。

实测结果：

  • r001 的 iptm 从 0.6844 跌至 0.13；
  • 提交得分从 0.32 跌至 0.10。

恢复 MSA（v2.1）后回到 0.33，r001 的 iptm 恢复至 0.68。

结论：Protenix 默认 MSA=True 是经过验证的配置，任何为省算力/时间做的默认值修改，必须先经一道题的提交验证再推广。 这一事故同时给出一个校准点：MSA 信号的贡献约值 0.23 总分，是全场单项贡献最大的因子。

4. 阶段三：r003 显存问题与降级方案（v2.1 → v3）

4.1 问题定性

r003 共 1415 tokens。base 模型在此规模下推理显存需求超出 24GB，直接 CUDA OOM。占总分 1/3 的赛题持续为零分，这是当时最大的失血点。

4.2 备选路径评估

当时有两条路径：

  1. 租用更大显存（AutoDL V100 32GB 约 2-3 元/小时，A100 40GB 约 6 元/小时）——预案已写好（含脚本与费用估算）；
  2. 在 24GB 内降级跑通。

优先尝试路径 2（零成本），路径 1 作为兜底。

4.3 降级方案

组合三项措施：

  • 换用 tiny 模型（protenix_tiny_default_v0.5.0，109.5M 参数，base 的约 1/3）；
  • PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True，解决 PyTorch 显存碎片化导致的"总量够、分配失败"；
  • --enable_cache false，关闭扩散共享变量缓存，让出常驻显存。

r003 跑通，iptm 0.224（质量不高，但非零）。提交得分 0.4417，单次涨幅 +0.11，为全场最大。

结论：多题等权赛制下，优先消除零分题。"有分"与"高分"是两个独立目标，前者优先。

5. 阶段四：采样与模型维度的系统性实验（v3 → v5）

基线稳定后，检验三个直观假设：

  1. 扩大采样池（r002 从 1 sample 扩到 5）：同题 5 个 sample 的综合分差异仅 0.3527–0.3622，提交后总分不变（0.33）；
  2. 多 seed（101/202/303 × 3 题）：候选间分数差异 <0.01，提交得分 0.33381，持平；
  3. 双模型对比（v0.5.0 vs v1.0.0）：v1.0.0 置信分更高，但后续提交证明实际更差（见阶段五）。

同期发现两个重要事实：

  • GPU 浮点非确定性：同 seed 同配置不同次推理，输出结构不完全一致（v5 重跑基线配置得 0.4325 / 0.4270，均低于此前同配置的 0.4417）。这意味着换 seed/重跑本质上是在随机分布中抽样，单次结果不可作为配置优劣的证据；
  • 参数量与效果不正相关：mini 模型（134M）在 r003 上 iptm 仅 0.16，反而低于 tiny（109M）的 0.22——小模型档位间存在训练充分度差异，不能按参数量线性外推质量。

结论：在评测反馈稀疏的赛制下，采样维度的边际收益趋近于零，且会消耗宝贵的提交次数。此后的算力转向结构性问题。

6. 阶段五：confidence 自动挑画的失败与域裁剪的否定（v4 → v6）

6.1 confidence 自动挑画（-0.12 事故）

v4 将挑画策略改为"全候选按模型自报 confidence 排序取最高"。该轮三题候选的置信分全面高于上一版（如 r001 ranking_score 0.70→0.78），但提交得分跌至 0.3247（-0.12）。

原因分析：模型自报的 iptm/ptm/ranking_score 与赛方评测指标（对照真实结构的 RMSD/TM-score/lDDT）仅弱相关，低置信区间尤甚。模型置信分可用于候选间相对排序的参考，不可作为提交决策依据；配置优劣的唯一判据是实际提交。

6.2 域裁剪（结构性失败）

为让 base 模型处理 r003，v6 尝试域裁剪：先做序列特征分析（N 端 ATPase/解旋酶域含 Walker A motif、跨膜区、1181-1250 高正电荷区为最强 RNA 结合信号），据此裁出 4 个片段（250–520aa）分别连同 RNA 用 base 推理。

结果 4 个方案全部劣于 tiny 全长（最好的 Trim B，iptm 0.217 vs tiny 全长 0.224，且提交后总分降至 0.3647）。

失败机理：蛋白质折叠依赖远程残基间的结构约束，被裁掉的区段即使不直接接触 RNA，也参与定义整条链的折叠势。对复合物预测模型做输入裁剪，破坏的是上下文先验，不可通过换大模型补偿。

7. 阶段六：复合物分解与推理链路改造（v7 → v9）

7.1 r002 子复合物分解

r002 全复合物 1114 tokens。注意到其组成（2×(A+B)+2×RNA）具有晶体学对称性，构造三个子复合物变体：

变体 组成 tokens 假设
asym A+B+RNA 各一条 557 不对称单元包含全部独特界面
homoA A×2 + RNA 570 保留 A 链二聚界面
homoB B×2 + RNA 544 保留 B 链二聚界面

其中 asym 最终进入最优组合。需说明：受提交次数限制，asym 与 full 未做隔离消融，其优势是与其它改动耦合验证的；homoA/homoB 未提交验证。

8. 阶段七：显存工程——confidence head 短路（v10 → v12）

8.1 原理

9. 阶段八：精修与最终方案（v11 → v12）

最后阶段的改动收敛为两处低风险参数调整：

  1. r001：n_cycle 10 → 20（recycle 轮数加倍，换取精化深度，代价是推理时间翻倍）；
  2. r002：采用 asym 子复合物（557 tokens）。

最终提交组合：r001 = base/cycle20/seed101/sample_0，r002 = asym/sample_0，r003 = base/monkey-patch/sample_0。

最终得分 0.44915，为全程最高，对应初赛排名 199/3475。

同样需说明：n_cycle=20 与 asym 两项改动未做隔离消融（每次提交都需同时覆盖三题，隔离验证成本为 2-3 次提交），其贡献是作为组合验证的。从 0.4417 到 0.44915 的增量中，r003 从 tiny 换为 base 全长的贡献预计占主要部分。

10. 赛后遗留：已实现未验证的方向

赛后（仍在赛期内）实现了四个方向，因提交窗口结束未完成验证，代码已就绪：

  1. 能量最小化后处理（v14）：PDBFixer 补缺失原子/氢 + OpenMM 局部能量最小化，消除几何畸变；
  2. 结构集成（v16）：Kabsch 对齐后对多 seed 候选做坐标平均；
  3. 备选模型（v15）：Chai-1（不同架构的复合物预测模型），用于结果交叉验证；
  4. 官方 baseline（v13）：赛方提供的 SAISfold 推理包，因环境问题未跑通。

12. 技术结论

关于小显存推理，按代价从低到高的处理阶梯（本次全程验证）：

  1. expandable_segments:True（治碎片，零精度损失）；
  2. 关闭推理缓存；
  3. bf16；
  4. 降 n_cycle / n_step（减精化与采样深度，不动模型容量）；
  5. 短路 confidence head（省 N² 级显存，代价是无自报分数）；
  6. 换小规格模型（注意档位间质量与参数量不成正比，tiny 优于 mini）；
  7. 输入序列裁剪（已证伪：上下文先验不可裁）。

关于实验方法：

  • 模型自报置信分与外部评测指标弱相关，只可作排序参考，不可作提交决策；
  • GPU 推理存在浮点非确定性，单次对比不构成配置优劣的证据；评测反馈稀疏时，应把提交次数留给结构性改动，而非采样维度；
  • 多题等权赛制下，消除零分题的期望收益远高于打磨高分题；
  • 默认配置承载了先验，修改前先做单题验证。

关于资源策略：免费算力的降级空间（模型档位 + 显存参数 + 模型结构补丁）远比直觉的大——本次 r003 从"完全无法运行"到"base 全长跑通"未花费一分钱租卡费用；付费算力预案应保留，但仅在免费路径穷尽后启用。
